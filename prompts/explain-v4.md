# 解説生成の指示（explain-v4）

> **この指示を変えたら版を上げる**（explain-v5.md を新しく作る。このファイルは編集しない）。
> v3 からの変更（T013・決定024）：民法の2019年以前の問も書く。現行の条文では公式の○×を説明できない肢（前提の制度がなくなった肢を含む）は、解説を書かずに `law_changed` に理由を書く（下の「民法の2019年以前の問」）。ほかの科目・年度の書き方は v3 と同じ。
> v2 → v3 の変更（T041・決定022）：判例は `pipeline/courts.py` で裁判所の判決のページを確かめる（WebSearch は判例の確かめに使わない）。確かめられない判例は `pending_cases` に残す。出題当時の旧法の中身を記憶で書かない。検索結果の要約も素材にしない。
> 生成は Claude Code のセッション（サブエージェントを含む）で行う。1問（その問の肢）ごとに1ファイル書き出し、チェックを通してから次の問へ進む。

## 入力（1問ごと）

- 正本 `data/questions/<exam>/<year>/<subject>.json` の、その問の**リード文・前提文（context）・小問・肢**（`python3 pipeline/explain_queue.py --show <exam> <year> <subject> <number>` で表示する）
- **肢ごとの公式の○×（`truth_at_exam.value`）**：固定。モデルが判定し直さない
- 根拠条文の本文：`python3 pipeline/egov.py <法令> <条>` で表示した、`data/statutes/` に保存済みの本文。法令名は `pipeline/egov.py` の `LAWS` の名前をそのまま使う
- 判例：`python3 pipeline/courts.py` で表示した、裁判所の判決のページの項目（判示事項・裁判要旨など）と判決全文

## 解説を書く肢

- その問の肢のうち、`truth_at_exam` があり、まだ解説がなく、名寄せで他のカードに読み替えられない肢だけ（`--show` の表示で「書く」とある肢）
- 名寄せで読み替えられる肢は書かない。書き出しのときに代表の肢の解説が共有される

## 守ること

1. **結論は公式の○×に合わせる。**書いている途中で「公式の○×は誤りではないか」と思ったら、解説を曲げずに `stated_truth` に自分の結論を書き、`notes` に理由を書く。チェックが食い違いとして止める（パースの誤り・正答表の読み違い・法改正の信号）
2. **条文の文言は、`data/statutes/` に保存した本文からだけ引用する。**記憶で条文を書かない。本文中で条文を引くときは「」で囲み、保存した本文の文字列と一致させる（チェックが照合する）。本文で「○条」と条番号に触れたら、その条を必ず `citations` に入れる。法令が保存済みかは、思い込まずに `egov.py` を実行して確かめる
3. **判例は `pipeline/courts.py` で確かめたものだけ載せる。**
   - まず `python3 pipeline/courts.py known <語>` で、ほかの解説で確かめ済みの判例がないか引く（あれば `show` で中身を確かめて使う）。なければ `search` で探す
   - 探す：`python3 pipeline/courts.py search <判示の語句> [--date YYYY-MM-DD] [--from 昭和40 --to 昭和50]`（最高裁判例だけ。下級審の裁判例を探すときは `--all` を付ける）。1語目は論点の中心の語、2語目以降は絞り込みの語（2語目以降は「すべて含む」で絞り込まれる。条番号は判示事項では漢数字のことが多い：「九四条二項」）。ヒットが2000件を超えると「検索できなかった（サイトのエラー）」と出る（「0件」ではない）ので、語を足して絞る。年月日が分かっていれば `--date` でほぼ1件に絞れる
   - 確かめる：`python3 pipeline/courts.py show <id>` で判示事項・裁判要旨を読む。要旨で足りないときは `python3 pipeline/courts.py pdf <id>` で全文を保存し、Read の道具で読む
   - `cases` の `court`・`date`（西暦の YYYY-MM-DD）・`case_number` は、`show` に出た法廷名・裁判年月日・事件番号に合わせる。`name` は何についての判例かが分かる短い呼び名（広く知られた通称でもよい。`show` の「事件名」は使わない）。`verified_urls` には `show` が表示した「確認に使う URL」を書く。`holding` は判示事項・裁判要旨・全文に書いてあることだけを短くまとめる
   - 1つの判例を探すのは検索3回まで。見つからなければ、本文に「判例あり（要確認）」と書き、`pending_cases` に「何についての判例か」と「試した検索」を残す（`cases` には入れない）
   - **WebSearch・解説サイト・予備校・出版社の解説・検索結果の要約は、判例の確かめに使わない**（素材にしない）。判決の日付・事件番号を記憶で書かない
   - 大審院の判決（昭和22年より前）はこのデータベースにないので、探さずに `pending_cases` に残してよい（`searched` に「大審院（データベースにない）」と書く）
4. **条文に書いていない解釈（学説・判例の一般的な理解）を書くときは、そうと分かる書き方にする**（「〜と解されている」）。`notes` に「解釈による」と残す
5. e-Gov の本文は**取得日時点の現行法**。**出題当時の旧法（改正前）の文言・数字・条番号の中身を記憶で書かない。**現行法の本文で説明し、改正で変わった点は `notes` に「改正前の内容は条文の本文で確認していない」と書く。現行の条文では公式の○×を説明できないときは、規則1のとおり `stated_truth` を自分の結論にして止める（**民法の2019年以前の問だけは、下の「民法の2019年以前の問」に従う**）
6. 問題文にない事実を足さない。肢の結論を分けるポイント（どの文言が誤りか）を最初に示す
7. **前提文が要る肢**（会話・見解・事例・本文に埋め込まれた肢など）は、前提文を読んだうえで、その肢がなぜ○×かを書く。前提文の文言を「」で引くときは問題文と一致させる。問題文に参照条文として載っている法令の中身は、その問題文を根拠にしてよい
8. **必要な法令が `LAWS` にない**ときは、記憶で条文を書かず、その問は書き出さずに、報告に「法令がない：<法令名>」と残す（法令を足すのはメインのセッション）。最高裁判所規則（刑事訴訟規則・民事訴訟規則）・大日本帝国憲法は e-Gov になく使えない。それで答えが決まる肢は書かずに報告する
9. 他のファイル（`pipeline/`・正本・`data/statutes/` など）は変えない。書くのは担当の問の解説ファイルだけ

## 民法の2019年以前の問（T013）

債権法改正（2020年4月施行）より前の出題。相続法・親族法・成年年齢などの改正もその後にある。**公式の○×は出題時点の正解で、変えない。今の法律での○×を言わない。**

1. 今の条文（e-Gov）で、公式の○×に行き着くかを確かめる
2. **行き着く** → いつもどおり解説を書く。`notes` に「現行の条文で説明した（出題は改正前）」と書く
3. 次のどれかなら、**解説（`conclusion`・`body`）を書かず**、`law_changed` に理由を書く。`stated_truth` は**公式の○×のまま**にする
   - 今の条文では、公式の○×に行き着かない
   - 肢の前提にしている制度・規定が今の条文にない（例：瑕疵担保責任・短期消滅時効・法定利率の固定の率など。今の条文で○×がたまたま合っても、前提が古ければこちら）
   - 結論は合うが、決め手の条文の中身が出題後に変わっていて、今の条文で説明すると出題の趣旨と別の理由になる
4. `law_changed` は1〜3文で「今の条文のどこが、肢の前提とどう違うか」。条文の文言は「」で引き、その条を `citations` に入れる（今の条文の本文と照合される。古い条文は引用できない）。古い条文の中身は書かない（読んで分かったことでも、引用はしない）。条番号に触れたら `citations` に入れる
5. **H29〜R01（2017〜2019年）の問**は、出題時点の条文を e-Gov の過去の版で読める
   - 引く条ごとに `python3 pipeline/egov.py 民法 <条> --asof <年>-05-01` で、出題時点（その年の5月1日の版）の本文を見る。「本文は変わっていない」と出れば今の本文と同じ。変わっていれば出題時点の本文が出るので、今の本文（`egov.py 民法 <条>`）と比べて、結論が変わるかを確かめる（読むだけ。引用は今の条文から）
   - 変わっていても結論が同じなら手順2（`notes` に「出題後に○条の本文が変わった（結論は同じ）」）。結論や理由が変わるなら手順3
   - H23〜H28（2011〜2016年）は過去の版がない（2016年10月より前の版は e-Gov にない）。この確かめはしない
6. 迷ったら手順3にする（解説を出さない方に倒す）

`law_changed` の肢の出力の形：

```json
{
  "target": { "type": "statement", "id": "yobi-2018-minpo-q20-a" },
  "version": 1,
  "stated_truth": false,
  "law_changed": "今の民法は売主の担保責任を契約不適合として定め（「…」）、肢の前提の瑕疵担保責任の規定はない。",
  "citations": [ { "type": "statute", "law": "民法", "article": "562", "paragraphs": ["1"], "quote": "…" } ],
  "notes": []
}
```

## 出力

`data/explanations/<exam>/<year>/<subject>/q<NN>.json`（NN は2桁。すでにファイルがあれば、既存の解説は残して足す）

```json
{
  "question_id": "yobi-2026-shoho-q16",
  "prompt_version": "explain-v4",
  "generated_at": "YYYY-MM-DD",
  "generated_by": { "model": "<モデル ID>", "via": "Claude Code セッション（サブエージェント）" },
  "explanations": [
    {
      "target": { "type": "statement", "id": "yobi-2026-shoho-q16-a" },
      "version": 1,
      "stated_truth": true,
      "conclusion": "1文で：○か×か＋決め手",
      "body": "3〜6文。条文の文言は「」で引用（保存した本文と一致）",
      "citations": [
        { "type": "statute", "law": "会社法", "article": "5", "paragraphs": ["1"], "quote": "保存した本文からそのまま抜き出した文" }
      ],
      "cases": [
        { "name": "何についての判例かが分かる短い呼び名", "court": "最高裁判所第一小法廷", "date": "YYYY-MM-DD", "case_number": "昭和45(オ)1055", "holding": "判示事項・裁判要旨・全文にあることを短く", "verified_urls": ["https://www.courts.go.jp/hanrei/52639/detail2/index.html"] }
      ],
      "pending_cases": [
        { "about": "確かめられなかった判例が何についてのものか（肢の論点を短く）", "searched": ["courts.py search 留置権 第三者 --from 昭和40 --to 昭和50"] }
      ],
      "notes": []
    }
  ]
}
```

- `article` は e-Gov の形（枝番は `98_2`）。`paragraphs` は項の番号（1始まり）。項のない条は `["1"]`
- `quote` は、その項の本文の部分文字列であること
- `pending_cases` は、本文に「判例あり（要確認）」を書いたときだけ入れる（ないときは項目ごと省くか空の配列）。チェックが本文と突き合わせる
- `verified_urls` は courts.go.jp の URL だけ
- 書き出したら `python3 pipeline/check_explanations.py <exam> <year> <subject> <NN>` を通す。❌ が出たら直して通し直す（2回まで）。それでも通らない肢は、そのまま（flagged のまま）にして報告する。食い違い（🔴）は直さずに報告する
- 「解説のない肢」の ❌（問単位）は、名寄せで書かなかった肢についてなら無視してよい
- `law_changed` の肢は、チェックで ⚖️（status: law_changed）と出れば正しい。❌ なら直す
