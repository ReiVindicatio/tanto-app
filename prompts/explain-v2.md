# 解説生成の指示（explain-v2）

> **この指示を変えたら版を上げる**（explain-v3.md を新しく作る。このファイルは編集しない）。
> v1 からの変更：全科目・全試験（予備・司法）を対象にした。前提文の要る肢・名寄せした肢・法令がそろっていないときの扱いを足した（T039・決定021）。
> 生成は Claude Code のセッション（サブエージェントを含む）で行う。1問（その問の肢）ごとに1ファイル書き出し、チェックを通してから次の問へ進む。

## 入力（1問ごと）

- 正本 `data/questions/<exam>/<year>/<subject>.json` の、その問の**リード文・前提文（context）・小問・肢**
- **肢ごとの公式の○×（`truth_at_exam.value`）**：固定。モデルが判定し直さない
- 根拠条文の本文：`python3 pipeline/egov.py <法令> <条>` で表示した、`data/statutes/` に保存済みの本文。法令名は `pipeline/egov.py` の `LAWS` の名前をそのまま使う（例：「日本国憲法」「行政事件訴訟法」）

## 解説を書く肢

- その問の肢のうち、`truth_at_exam` があり、まだ解説がなく、名寄せで他のカードに読み替えられない肢（`app/public/data/index.json` の `aliases` のキーにない肢）だけ。`python3 pipeline/explain_queue.py` が数えている肢と同じ
- 名寄せで読み替えられる肢（他の出典と同じ肢）は書かない。書き出しのときに代表の肢の解説が共有される

## 守ること

1. **結論は公式の○×に合わせる。**書いている途中で「公式の○×は誤りではないか」と思ったら、解説を曲げずに `stated_truth` に自分の結論を書き、`notes` に理由を書く。チェックが食い違いとして止める（パースの誤り・正答表の読み違い・法改正の信号）
2. **条文の文言は、`data/statutes/` に保存した本文からだけ引用する。**記憶で条文を書かない。本文中で条文を引くときは「」で囲み、保存した本文の文字列と一致させる（チェックが照合する）。本文で「○条」と条番号に触れたら、その条を必ず `citations` に入れる
3. **判例は、検索で確認できたものだけ載せる。**裁判所の裁判例検索（courts.go.jp）など、判決を確認できるページで、事件の呼び名・裁判所・年月日・判示の要旨を確かめ、確認した URL を `verified_urls` に書く。2回探して確認できないときは本文に「判例あり（要確認）」とだけ書き、`cases` には入れない。予備校・出版社など他社の解説・分類・肢別本は見ない・使わない（判決そのものの確認に限る）
4. **条文に書いていない解釈（学説・判例の一般的な理解）を書くときは、そうと分かる書き方にする**（「〜と解されている」）。必要なら `notes` に「解釈による」と残す
5. e-Gov の本文は**取得日時点の現行法**。出題時点から改正がありうる年度では、改正の有無に気づいたら `notes` に書く。現行の条文では公式の○×を説明できないときは、規則1のとおり `stated_truth` を自分の結論にして止める（公式の○×に合わせて理屈を曲げない）
6. 問題文にない事実を足さない。肢の結論を分けるポイント（どの文言が誤りか）を最初に示す
7. **前提文が要る肢**（会話・見解・事例・本文に埋め込まれた肢など）は、前提文を読んだうえで、その肢がなぜ○×かを書く。「本問の見解によれば」のように前提文に触れてよい。前提文の文言を「」で引くときは問題文と一致させる
8. **必要な法令が `LAWS` にない**ときは、記憶で条文を書かず、その問は書き出さずに、報告に「法令がない：<法令名>」と残す（法令を足すのはメインのセッション）
9. 他のファイル（`pipeline/`・正本・`data/statutes/` など）は変えない。書くのは担当の問の解説ファイルだけ

## 出力

`data/explanations/<exam>/<year>/<subject>/q<NN>.json`（NN は2桁。すでにファイルがあれば、既存の解説は残して足す）

```json
{
  "question_id": "yobi-2026-shoho-q16",
  "prompt_version": "explain-v2",
  "generated_at": "YYYY-MM-DD",
  "generated_by": { "model": "<モデル ID>", "via": "Claude Code セッション（サブエージェント）" },
  "explanations": [
    {
      "target": { "type": "statement", "id": "yobi-2026-shoho-q16-a" },
      "version": 1,
      "stated_truth": true,
      "conclusion": "1文で：○か×か＋決め手",
      "body": "3〜6文。条文の文言は「」で引用（保存した本文と一致）",
      "citations": [
        { "type": "statute", "law": "会社法", "article": "5", "paragraphs": ["1"], "quote": "保存した本文からそのまま抜き出した文" }
      ],
      "cases": [
        { "name": "事件の呼び名", "court": "最高裁判所第三小法廷", "date": "YYYY-MM-DD", "holding": "判示の要旨（自分の言葉で短く）", "verified_urls": ["https://www.courts.go.jp/..."] }
      ],
      "notes": []
    }
  ]
}
```

- `article` は e-Gov の形（枝番は `98_2`）。`paragraphs` は項の番号（1始まり）。項のない条は `["1"]`
- `quote` は、その項の本文の部分文字列であること
- 書き出したら `python3 pipeline/check_explanations.py <exam> <year> <subject> <NN>` を通す。❌ が出たら直して通し直す（2回まで）。それでも通らない肢は、そのまま（flagged のまま）にして報告する。食い違い（🔴）は直さずに報告する
- 「解説のない肢」の ❌（問単位）は、名寄せで書かなかった肢についてなら無視してよい
