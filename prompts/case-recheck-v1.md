# 判例の確かめ直しの指示（case-recheck-v1）

> **この指示を変えたら版を上げる**（case-recheck-v2.md を新しく作る。このファイルは編集しない）。T041・決定022。
> 既存の解説の判例を、裁判所の判決のページで確かめ直す。対象の問は `python3 pipeline/case_queue.py --next N` が出す。1問（その問の解説ファイル）ずつ直し、チェックを通してから次の問へ進む。

## 対象

`data/explanations/<exam>/<year>/<subject>/q<NN>.json` の肢の解説のうち：

- **① 第三者サイトで確かめた判例**：`cases[].verified_urls` に `https://www.courts.go.jp/` 以外の URL がある
- **② 確かめられていない判例**：本文に「判例あり（要確認）」があり、`pending_cases` がない

それ以外の肢の解説は変えない。

## やること

### ① の判例

1. `python3 pipeline/courts.py search <判示の語句> --date <cases の date>` で探す（`--date` は「1982-06-08」「昭和57年6月8日」のどちらの形でもよい。日付が合わなければ `--from/--to` で前後の年も）
2. 見つかったら `python3 pipeline/courts.py show <id>` で判示事項・裁判要旨を読み、`cases` を直す（形は下の「cases の形」）
   - `verified_urls` を `show` が表示した「確認に使う URL」だけにする（第三者サイトの URL は消す）
   - `holding` を判示事項・裁判要旨・全文に書いてあることに合わせる（第三者サイトの言い回しを残さない）
3. 検索3回で見つからなければ、その判例を `cases` から外し、本文の判例の記述を「判例あり（要確認）」に置き換え、`pending_cases` に残す

### ② の判例

1. 本文と `notes` から、何についての判例かを読み取る
2. `courts.py search` で探す（検索3回まで）。大審院の判決（昭和22年より前）はデータベースにないので探さない
3. 見つかったら：`show`（必要なら `pdf`）で中身を確かめ、`cases` に入れる。本文の「判例あり（要確認）」を、確かめた判例を示す書き方に直す（例：「最高裁昭和47年11月16日判決は、…とした」）。判決に書いていないことを判例の判示として書かない
4. 見つからなければ：本文はそのままにし、`pending_cases` に `{"about": "何についての判例か", "searched": ["試した検索", …]}` を書く
5. 本文に判例の中身を「〜と解されている」の形で書いている箇所は、確かめた判決と合わなければ、判決に合わせて直すか、確かめられない部分を削る

### 検索のコツ（試しで分かったこと）

- 語句をたくさん並べるより、判示事項に出る表記を1〜2語で探し、`--date` で絞るほうが当たる。条番号は判示事項では漢数字のことが多い（「九四条二項」）
- 日付が分かっていれば、`courts.py search <1語> --date <日付>` でほぼ1件に絞れる。0件なら語を変えるか、語を1つ減らす

### cases の形

```json
{ "name": "何についての判例かが分かる短い呼び名", "court": "最高裁判所第三小法廷", "date": "1982-06-08",
  "case_number": "昭和56(オ)988", "holding": "判示事項・裁判要旨・全文にあることを短く",
  "verified_urls": ["https://www.courts.go.jp/hanrei/70440/detail2/index.html"] }
```

- `court`・`date`（西暦の YYYY-MM-DD）・`case_number` は `show` の表示（法廷名・裁判年月日・事件番号）に合わせる
- `name` は、何についての判例かが分かる短い呼び名（例：「土地の仮装譲受人が建てた建物の賃借人と94条2項の第三者」）。広く知られた通称がある事件は通称でもよい。`show` の「事件名」（「建物退去土地明渡」など）は何の判例か分からないので `name` にしない
- 古い解説にある `verification` の項目は消す（explain-v1 の項目で、今は使わない）

### どちらでも

- 直した肢の解説は `version` を1つ上げ、`notes` に「判例を確かめ直した（T041・case-recheck-v1・YYYY-MM-DD）」と残す。直さなかった肢（② で見つからず `pending_cases` を書いただけの肢）も同じメモを残す（`version` は上げない）
- **公式の○×（`stated_truth` と正本）には触れない。**確かめた判決が肢の結論（公式の○×）と合わないときは、解説を直さずに、報告に「🔴 判決と公式の○×が合わない：<肢ID>（理由）」と書いて、その問は止める
- 条文の引用・本文の「」は今の解説のまま残す。直した本文で新しく条文を引くときは `python3 pipeline/egov.py` で表示した本文だけ
- **WebSearch・解説サイト・予備校・出版社の解説・検索結果の要約は使わない**
- 書いたら `python3 pipeline/check_explanations.py <exam> <year> <subject> <NN>` を通す。❌ が出たら直して通し直す（2回まで）。⚠ のうち「pending_cases がない」「courts.go.jp 以外の URL」が残っていたら、やり残しがある
- 書いてよいのは担当の問の解説ファイルだけ。git の操作はしない
