# 判例は裁判所の判決のページだけで確かめ、確かめられない判例は pending_cases に残す（2026-10-21）

> 決定の記録。**以後編集しない。**手順の現行版は `prompts/explain-v3.md`・`prompts/case-recheck-v1.md`・`prompts/explain-runbook.md`。T041。

## 何が起きたか

- 解説 4,650件のうち、本文が「判例あり（要確認）」のものが 627件、判例を `cases` に載せたものが 997件あった
- `cases` の確認に使った URL（`verified_urls`）に、**law-lib.jp（90件）・takken-success.info（2件）といった第三者のサイトがあった**。民法 R02〜R08 の42問（explain-v1、2026-10-18〜19 生成）。禁止事項1・4に反する疑い。検査はどのサイトの URL かを見ていなかった
- 判例の確かめは WebSearch → 判決のページの形で、古い判決・決定がヒットしにくかった。裁判例検索のページは「JavaScript で描くので読めない」と思われていたが、**検索語・日付を URL に付けて GET すれば、サーバーが結果の一覧を返す**と分かった（2026-10-21 の下調べ）
- 連続生成（T039）の中でも、検索結果の要約から判例の理由づけを書いた例があった（メインのセッションが外した）

## 決めたこと（ユーザーと合意）

- 判例は `pipeline/courts.py`（裁判所の裁判例検索・判決のページ・判決全文を取る道具）で確かめたものだけ載せる。**WebSearch は判例の確かめに使わない**（検索結果の要約が素材に混じる危うさを断つ）
- 確かめられない判例は、本文の「判例あり（要確認）」に加えて、解説の `pending_cases`（何についての判例か・試した検索）に残す。アプリには書き出さない
- 判例の確かめ直しの範囲は、① 第三者サイトで確かめた判例（42問）と ② 「判例あり（要確認）」。「〜と解されている」と書いた解釈（約2,156件）は今回は扱わない
- 検査を2段階で強める：本文の「判例あり（要確認）」と `pending_cases` の突き合わせ（explain-v3 以降は ❌、それより前は確かめ直すまで ⚠）、`verified_urls` は courts.go.jp だけ（① を直し終えてから ❌ にする。それまでは ⚠）
- 解説の生成の指示を explain-v3 に上げ、T039 の残りは v3 で書く

## 残る危うさ

- 大審院の判決（昭和22年より前）は裁判例検索にないとみられ、その判例は `pending_cases` のまま残る
- 判示事項・裁判要旨で確かめた判例でも、肢に当てはめる理屈は解説を書いたモデルの解釈。「〜と解されている」の部分は検査で裏付けられない
