# 開発をチケット（tickets/）で管理する（2026-10-18）

> 決定の記録。**以後編集しない。**運用の現行版は `tickets/README.md`。

## 何が起きたか

予備 R08 の刑法・民法で、データの取り込み・解く画面・解説・正答履歴・FSRS まで一通りできた。ユーザーから「何ができていて何ができていないか分からない。機能ごとに割って、設計・レビュー・実装と進めたい。実装したいもののリストを作り、起票・議論中などの状態で管理したい」と要望があった。

## 決めたこと

- 作りたいもの・直したいものは `tickets/T<番号>-<名前>.md` に1件1ファイルで貯め、`tickets/README.md` のボードで状態を管理する
- 状態：起票 → 議論中 → 設計中 → 設計レビュー → 実装中 → 実装レビュー → 完了（保留・却下）
- 設計レビューは、スキーマ・データ・方針・学習記録・外部サービスに触れるものでは必須。小さな UI・文言・バグ修正は省略可（チケットに明記）
- できていること・できていないことの全体は `docs/features.md` に置き、機能が変わったら更新する
- マイルストーン：M1 基盤 → M2 拡充 → M3 公開。**M1 の全チケットが完了したら、Claude から「基盤ができた」と伝える**
- NOW.md は「いま進めているチケットと、次の一手」を書く場所にする（作業のリストはチケットへ）

## 置き場をリポジトリ内の Markdown にした理由

- GitHub Issues も使えるが、設計をチケットにそのまま書け、Claude のセッションからオフラインでも読み書きでき、変更履歴が git に残る
- 外部サービスに書き込む操作（Issue の作成）を毎回確認せずに済む

## 採らなかったこと

- **GitHub Issues／Projects**：ボードの見た目は良いが、上の理由で見送り。必要になれば移せる
