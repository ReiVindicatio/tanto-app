# 解説は1問ずつ書き出し、1セッションで5問程度まで進める（2026-10-18）

> 決定の記録。**以後編集しない。**運用の現行版は `CLAUDE.md`・`prompts/explain-vN.md`。

## 何が起きたか

民法 R08 問1で解説の仕組み（`prompts/explain-v1.md`・`pipeline/egov.py`・`pipeline/check_explanations.py`）を作り、5肢すべてが検査を通った。ユーザーから「5問ずつ一気に作るほうがよければそれでもいい」と言われた。

## 決めたこと

- 生成と書き出しの単位は**1問（その問の肢すべて）＝1ファイル**のまま。1問書くたびに `check_explanations.py` を通してから次へ進む
- **1回のセッションで5問程度まで進めてよい**（CLAUDE.md の「1回のセッションで1問ずつ」を改める）
- 解説ファイルは設計 §3.5 の「肢ごとに1ファイル」ではなく、**問ごとに1ファイル**（`data/explanations/<exam>/<year>/<subject>/qNN.json`）。中に肢ごとの解説を持つ

## 理由

- 手間の大半は裏取り（条文の取得・照合、判例の確認）で、仕組みは問1で固まった。1問ずつ書き出せば、途中でトークンが切れても次のセッションは続きから再開できるので、まとめて進めても失うものがない
- 問ごとのファイルにすると、生成の単位・再開の単位・チェックの単位が一致する
