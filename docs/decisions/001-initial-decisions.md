# 初期の決定5つ（2026-10-18）

> 決定の記録。**以後編集しない。**運用の現行版は `CLAUDE.md`・`docs/design.md`。

## 何が起きたか

設計提案（`docs/design.md` の初版）の最後に「決めてほしいこと」を3つ置き、ユーザーが答えた。あわせて、ホスティングの選び方を聞かれた。

## 決めたこと

1. **解説の生成は Claude Code のセッションで行う。**API の Batch は使わない
   - ユーザーの実績：「昔料理のサイト作った時、600個の料理について解説フルで作らしたけど割と問題なくできた」「ちまちま作って来ましょう。token切れたらまた数時間後って感じで」
   - そのため、生成は**1問ずつ・1問ごとに書き出す**形にし、途中で止まっても再開できるようにする。再現性は、指示ファイルの版（`prompts/explain-vN.md`）と解説ファイル側の記録で補う
2. **自分専用で使い始めるが、いつでも公開できる状態を保つ**（出典表記・AI 生成表示・秘密情報を commit しない・検証済みデータだけ書き出す）
3. **司法試験の短答も入れる。**外す理由がない（ユーザー：「司法試験を外す理由なんてないよね？」）。予備と司法で同じ問題が出ている場合に同じ肢を2枚のカードにしないよう、**同一肢の名寄せ**を設計に入れる
4. **ホスティングは静的サイトから始める。第一候補は Cloudflare Pages**
   - データ（問・肢・解説）は変化の少ない静的 JSON で足りる。復習の記録は端末内（IndexedDB）に置けば、サーバーなしで動き、オフラインでも使え、Capacitor にもそのまま載る
   - 🔍 **Vercel の Hobby（無料）プランは商用利用を禁じており、広告（AdSense を含む）を載せるのは商用利用に当たると明記している**（Vercel Fair use Guidelines）。広告収入を考えるなら Pro（有料）になる
   - 🔍 GitHub Pages も、オンラインビジネス向けの無料ホスティングとしての利用を認めていない（二次資料による）
   - Cloudflare Pages は、商用利用の禁止が見当たらないとする二次資料がある（⚠️ Cloudflare の利用規約そのものは未確認。公開前に確認する）
5. **Supabase は、端末をまたいだ同期と、報告タブを公開するときに入れる。**最初は入れない
   - 🔍 無料プランは1週間アクセスがないとプロジェクトが一時停止される（二次資料による）。自分専用の段階では、使わない週に止まる不便が出る
   - 自分専用のうちは、報告は端末内に保存するか GitHub の Issue に飛ばす形で足りる

## 採らなかったこと

- **API の Batch で一括生成**：費用は小さいが、ユーザーが Claude Code での生成を選んだ。生成の単位を小さくして品質を見ながら進められる利点もある
- **最初から Supabase を入れる**：データが静的なので不要。認証・同期は公開の段階で足す
