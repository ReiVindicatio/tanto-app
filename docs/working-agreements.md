# これまでに決まった進め方と好み

コードや git の履歴からは分からない、ユーザーと決めたこと。🔴 の禁止事項は `CLAUDE.md`。ここに書いてあることより、ユーザーが今言ったことを優先する。

ユーザー個人のことはここに書かない（リポジトリは public）。

## やりとり

- ユーザー向けの文は、途中の報告も含めてすべて日本語。サブエージェントの報告が英語でも日本語にする
- 楽観的な見通しより、構造的な問題点とデータの危うさを先に言う
- 確かめていないことは、確かめていないと書く。実機で見ていないものは「スマホ幅のブラウザまで」と書く
- 作ったものを見せるときは、動くものや一覧で見せる。作る前に案を見せてほしいものは先に見せる（衣装のモーションなど）

## テストと push

- テストの結果は終了コードで分岐してから push する（落ちたまま push した失敗が1回ある。`5b467b0`）
- push のあとは CI も見る。配信は CI を待たないので、落ちていたらすでに本番に出ている
- 足したテストは、直した箇所を一時的に外して落ちることも確かめる
- commit と push の決まりは `CLAUDE.md`

## 機能案の好み

**喜ばれる方向**：本物の過去問を深く学ぶもの。公式の素材の上に AI を載せて、そうと表示するもの（聞き流しの声、ひっかけの型、よく似た肢）。本番に近いもの（模試）。条文からの逆引き。使い心地の整理。

**却下されたもの**（ユーザーが言い出すまで再提案しない）：早押しや2択のゲーム、Duolingo 風の仕組み（学習の道・毎日のクエスト・ストリークのお守り・実績）、条文や判例の穴埋め（「オリジナル問題になっちゃう」）、プッシュ通知、一般教養、スマホアプリ。

**律については別**（2026-10-27〜）：律の成長や衣装といった見た目の報酬はよい。量ではなく学習の質につながる形にする。学習で有利にしない。

案が尽きたら、無理に出さず、使ってみて引っかかったことから決めることを提案する。

## 課金衣装

- **方向**：律の衣装を将来の課金要素にする。決済は頼まれるまで作らない。衣装は簡単に手に入らないようにする
- **1着ずつ確認しながら作る**：見本・服・お披露目など段階ごとに見せて合意してから次へ。無人で一括に作らない。無人で4着作ったとき、服の穴や下半身の消失が人の目に触れないまま進んだ。ふつうの衣装の足のコマのような機械的な作業は、一括で流してから全部見せてよい
- **「普通の動き」と「想像外の動き」を混ぜる**：Apex のスーパーレジェンド、レイスのクナイのように、衣装ごとに想像の外にある動きを入れる。動きをまねるのではなく別のものを考える。作る前にアイデアノートを見せる
- **見切れは禁止。継ぎ目はピタッと重ねる**
- **律を押す＝固有モーション。全画面の技は節目だけ**（全問正解・レベルアップ・お披露目）と律のページの「決め」
- **背景を動かすのは課金衣装だけ**
- **このあと作るもの**：マーチングバンドが案として残っている（クレジット不足で止めた）。詳細は `docs/ritsu-special-costumes.md`。実在のバンドに似せない

## 律を描くときの決まり

- 律の設定は約15歳。**肌の露出を増やさない。体を強調しない**
- 実在の人物・声優・VTuber・既存のキャラクター・他のゲームの衣装に似せない
- 律は法律の中身を言わない（決まったセリフだけ）
- 画像や動画のモデルが無害な内容を誤って断ったら、指示文を言い換えて作り直してよい（「生成できることが一番」）。結果だけ報告する。上の決まりに触れる内容を通すための言い換えはしない
- 誤って断られやすかった言い方：「手を胸や脚に…」「about 15 years old」。動きの指示からは外す

## 費用
