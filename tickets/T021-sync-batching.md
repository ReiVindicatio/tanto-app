# T021 同期の回数を減らす（まとめて送る）

- 状態：設計レビュー
- マイルストーン：M2 拡充
- 優先度：高
- 依存：
- 更新：2026-10-19

## 目的・背景

- 今は1回答ごとに API を2回（送る・受け取る）呼んでいる。Workers の無料の上限は API の呼び出しが1日10万回なので、全員の合計で1日5万回答で届く（D1 の書き込みの上限より先に届く）
- ユーザーの指摘（2026-10-19）：「何人かが使ったら一瞬で終わるよね」

## 議論（論点の候補）

- 送る：回答のたびではなく、数秒〜数十秒ためてまとめて送る／画面を閉じるとき（`visibilitychange`）に送る
- 受け取る：起動時・ログイン時・オンライン復帰時・画面に戻ったときだけ（回答のたびには受け取らない）
- 目安：1人1日 数回〜十数回の呼び出しに減らす

## 設計

### いまの呼び出し

- 回答のたびに `sync()` → 「送る（POST）」と「受け取る（GET）」で **1回答につき2回**
- 例：1人が1日200肢 → 400回。Workers の無料の上限（1日10万回）に、全員の合計で約250人分で届く

### 変えること

| | いま | 変更後 |
|---|---|---|
| 送る | 回答のたびに | **ためてまとめて送る**：最後の送信から60秒たったとき、未送信が30件たまったとき、画面を閉じる・別のアプリに切り替えるとき（`visibilitychange` で隠れたとき・`pagehide`） |
| 受け取る | 回答のたびに | **起動時・ログイン時・オンライン復帰時・画面に戻ったとき（前回から5分以上たっていれば）だけ** |

- `SyncedStore` の `sync()` を「送る（`flush`）」と「受け取る（`pull`）」に分け、回答時は `flush` の予約だけをする
- 画面を閉じるときの送信は、`fetch` の `keepalive` を使う（ページが閉じても送信が続く。本文は64KBまでなので、そのときは先頭の300件までを送り、残りは次の起動で送る）
- 送れなかった分は今まで通り未送信の箱に残り、次の機会に送られる（失われない）
- ヘッダーの表示は「未送信 N 件」が出る時間が今より長くなる（数十秒）。表示はそのまま

### 呼び出しの目安（変更後）

- 30分ずっと解いて：送る 約30回＋受け取る 1〜数回 → 1日1回30分なら **1人約35回／日**（今の 約1/10）
- 上限の目安：1日10万回 ÷ 35回 ≒ **約2,800人／日**まで無料

### テスト

- 単体（偽の時計で）：回答のたびには送らない、60秒・30件・画面を隠したときに送る、送った後に受け取らない、画面に戻ったときは5分以上たっていれば受け取る
- E2E：肢を10枚解いたあいだに API が呼ばれた回数を数え、回答の数より十分少ないこと。画面を隠す操作で未送信が0になること
- 同期の E2E（2つのブラウザ）は、片方で解いたあと「画面を隠す」→ もう片方で「画面に戻る」で反映されることを確かめる形に直す

## 設計で決めてほしいこと

1. 送る間隔（60秒・30件）と、受け取る間隔（画面に戻ったときは5分以上たっていれば）はこれでよいか
2. 別の端末の記録が反映されるのは「起動時・画面に戻ったとき」になる（解いている最中には反映されない）。これでよいか

## 完了条件

- 回答のたびに API を呼ばない（E2E で呼び出しの回数を数えて確かめる）
- 閉じる直前の回答が失われない（未送信の箱に残り、次の起動で送られる）
