# T076 聞き流しが止まる・二度押しで入れ替わった先まで押すバグ

- 状態：完了

- 優先度：高
- 依存：なし
- 更新：2026-11-09

## 目的・背景

2026-11-09 ユーザーの報告：聞き流しで○×や一時停止を押していたとき、次の肢へを押しても読み上げが始まらないことがあった（一時停止を2回押すと始まった）。ほかにも、いじってみないと分からない動作のバグを探してほしい（発見的なバグ探し）。

ボタンをでたらめな順・間隔で押す「いたずら押し」の E2E を作り、`<audio>` を本物に近い作り物（読み込み中に止める・別の音声に差し替えると play() が AbortError で断る、読み終わりは pause → ended）に差し替えて探した。見つかったもの：

1. **聞き流し：次の肢へ・再開のあと、Wake Lock（画面を消さない仕組み）の返事を待ってから読みはじめていた。**スマホでは返事に時間がかかり、その間は「▶ 再開」のまま音が出ない。そこで押し直すと、読み上げの流れが2本・3本と同時に走り、1つの `<audio>` を取り合う（いたずら押しで最大6本）。Wake Lock の返事を 250ms にすると、12通り中4通りで再現した
2. **聞き流し：外から音声を止められると（電話・通知・ほかのアプリの音）、止まったまま「考える時間 あと3秒」などと出し続けた。**一時停止→再開で続きが流れる（ユーザーの「一時停止を2回押すと始まった」と合う）
3. **肢で解く：○×と次へは同じ場所で入れ替わるので、二度押しで入れ替わった先まで押していた。**○の二度押しで答え合わせを見ずに次の肢へ、次へ の二度押しで次の肢に×と答えて記録（復習の期限・累計に入る）。真ん中を押すと○と×のすき間（10px）に当たって無事で、少し左右にずれると起きる
4. **問で解く：採点する の二度押しで、結果を見ずに次の問へ進んでいた**（3と同じ形）

アプリ全体のいたずら押し（見えているボタン・リンクを 32通り×120回）では、例外・console.error・真っ白な画面は出なかった。

## 議論（決まったこと）

設計レビュー省略（バグ修正。データ・スキーマ・方針に触れない）。

## 設計

- 聞き流し（`ListenPlayer.tsx`）
  - `begin()` は Wake Lock の返事を待たずに流れを始める（`holdScreen()`：返事が来る前に解除されたら、来たときに解除する）
  - 流れは1本だけ：`begin()` は前の流れを止めてから始める。`resume()` は流れが動いているとき（ロック画面の再生ボタンを流している最中に押したなど）は何もしない
  - 次の肢へ・再開は、描画を待たずに今の肢（`at` の ref）から決める（続けて押しても飛ばし損ねない）
  - `<audio>` の pause を見張り、外から止められたら一時停止にする。読み終わり（ended）・自分で止めてすぐ次を流したとき（○×・次の肢へ）・端末の読み上げ中・読めなかった音声は数えない。自分で止めたときは流れがすぐ次の音声を流すので、50ms おいてから確かめる
- 二度押し（`swapGuard.ts` の `useSwapGuard`）：下の欄のボタンが入れ替わった直後の 350ms だけ、欄に `settling` を付けて CSS でボタンを押せなくする（`pointer-events: none`。見た目は変えない。キーボード・スワイプはそのまま）。肢で解く・問で解くの欄に付ける
- テスト
  - `e2e/listen-monkey.spec.ts`：いたずら押し（音声あり・音声なし（端末の読み上げ）・Wake Lock 250ms の各4通り）。止まらず進むこと、ended を待つ流れが2本以上にならないこと。加えて、一時停止中の次の肢へがすぐ始まる（Wake Lock 1.5秒でも）、外から止められたら一時停止→再開で続く、○×で答えに進むときは外から止められたと見なさない
  - `e2e/double-tap.spec.ts`：○の二度押し・次へ の二度押し・採点する の二度押し
  - `e2e/monkey-app.spec.ts`：アプリ全体のいたずら押し（8通り×120回。例外・console.error・真っ白な画面）

## 完了条件

- 3つのテストが通る
- 本番の聞き流しで、一時停止→次の肢へ→すぐ再開 を押しても読み上げが1本で進む（ユーザーの実機）
