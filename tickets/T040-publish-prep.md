## 議論（決めること）

### 1. 退会

| 案 | 内容 |
|---|---|
| **A（勧め）** | マイページのアカウント欄の一番下に「記録を全部消す」。押すと件数（回答 n 件）を見せて確認、もう一度確認してから消す。ログイン中はサーバーの回答ログ＋この端末の記録を消し、Firebase のアカウントも消す（`user.delete()`。最近ログインしていないと再ログインを求められる）。ログインしていなければ「この端末の記録を消す」だけ |
| B | サーバーの記録だけ消し、Firebase のアカウントは残す（ログインし直せば空から始まる） |

- 勧めの理由：「退会」と書く以上、アカウント（Google との紐づけ）も消えるのが自然。B だと Firebase に利用者の名前・メールが残り続ける

### 2. 誤り報告（T015）

| 案 | 保存先 | 良い点 | 気になる点 |
|---|---|---|---|
| **A（勧め）** | D1 に `reports` 表を足す。Worker の `POST /api/reports` | 外部サービスが増えない。Claude のセッションで `wrangler d1 execute` で一覧を取り、処理できる | スキーマが増える（合意が要る）。通知はない（見に行く） |
| B | GitHub の Issue を Worker から作る | 通知が来る・一覧が見やすい | Worker に GitHub のトークンを置く。報告の文が公開リポジトリに出る（個人の文章が公開される） |
| C | Google フォームへのリンク | 作るものがほぼない | 肢 ID を自動で入れにくい。外部サービスが増える |

- A の中身（案）：肢・問の画面と解説の下に「誤りを報告」。種別（問題文・○×・解説・その他）＋自由記述（500字まで）。対象の ID・アプリの版・日時は自動で付ける。**ログインしている人だけ**（荒らし対策と、3の制限を uid で数えるため）
- 報告への返事はしない（返事の手段を持たない）。対応したかは解説の版で分かる
- `truth_wrong`（○×の誤り）の報告は、公式の○×を変えない（禁止事項2）。パースの誤りか法務省の正誤訂正かを調べ、正誤訂正なら T006 の手順で取り込む

### 3. 使いすぎの制限

| 案 | 内容 | 気になる点 |
|---|---|---|
| **A（勧め）** | Cloudflare Workers の Rate Limiting（Worker の設定に `ratelimits` を足す）。uid ごとに「1分に n 回」まで。超えたら 429 を返し、アプリは次の送信まで待つ | 無料プランで使えるか・数え方（場所ごとの概算）は実装前に確かめる |
| B | D1 に uid ごと・日ごとの回数を数える | 数えるための書き込みで、かえって D1 の無料枠を食う |
| C | 1日の回答数に上限（例：1人1日5,000件）を足す | A と併用するもの。正当な使い方で届かない数にする |

- 勧め：A（1分あたり）＋C（1日あたり、`POST /api/answers` の件数で数える）。今のアプリの正常な使い方（60秒・30件ごとにまとめて送る：T021）では届かない値にする
- 報告（2）にも同じ制限をかける（1人1日20件など）

- ユーザーが決めること：

  - **問い合わせ先**：メールアドレス／GitHub／報告機能（2）だけ
  - **書く内容**（Claude の案）：集める情報（Firebase の uid・回答ログ・アクセスログ。名前とメールは Google／Firebase が持つ）、使う目的（端末間の同期だけ）、預け先（Google Firebase・Cloudflare）、消し方（1の退会）、AI 生成の解説は正確さを保証しないこと、法務省とは関係がないこと、予告なく止めることがあること

## 設計

> 2・3 はスキーマと Worker の設定の変更なので、設計レビューを省かない。

### 1. 退会（記録を全部消す）

- **画面**：マイページのアカウント欄の一番下に「記録を全部消す（退会）」（危険な操作として赤い文字のボタン）
  - 押すと確認の欄が開く：「回答 n 件の記録を消します。ログイン中ならアカウントも消します。元に戻せません」＋「消す」「やめる」
  - 「消す」を押すと、さらにブラウザの確認（`confirm`）で2回目の確認
- **ログイン中**の順序：
  1. 未送信の箱を捨てる（送らない）
  2. `DELETE /api/me`（サーバーの回答ログを消す。報告〔2〕は消さずに、送った人の uid だけ消す：下の「報告と退会」）
  3. Firebase のアカウントを消す（`user.delete()`）。「最近ログインしていない」で断られたら、もう一度 Google のログイン画面を出して（`reauthenticateWithPopup`）やり直す
  4. 端末の記録（回答ログ・未送信・同期の印）を消し、ログアウトの状態にする
  - 2 が失敗したら、何も消さずに止めて「通信できませんでした」と出す。3 が失敗したら（再ログインを断られたなど）、サーバーの記録は消えているので「記録は消しました。アカウントの削除はできませんでした。もう一度お試しください」と出す
- **ログインしていない**とき：「この端末の記録を消す」だけ（4 だけ）
- `AuthClient` に `deleteAccount()` を足す（Firebase 版・テスト用の両方）。`SyncedStore` に `deleteAll()` を足す（logout と同じ後始末に、API の削除を加えたもの）

### 2. 誤り報告

- **D1 の表**（`app/migrations/0002_reports.sql`）：

  ```sql
  CREATE TABLE reports (
    id          TEXT NOT NULL PRIMARY KEY,  -- 端末で作る UUID（送り直しで重複しない）
    user_id     TEXT,                       -- Firebase の uid。退会したら NULL にする
    target      TEXT NOT NULL,              -- 肢 ID（yobi-2024-minpo-q01-a）または問 ID
    kind        TEXT NOT NULL,              -- question（問題文）／truth（○×）／explanation（解説）／other
    body        TEXT NOT NULL,              -- 500字まで
    context     TEXT NOT NULL,              -- JSON：解説の版（prompt_version・generated_at）・データの版など。アプリが自動で付ける
    created_at  TEXT NOT NULL,              -- サーバーが受け取った日時
    status      TEXT NOT NULL DEFAULT 'open' -- open／done／wontfix（Claude のセッションで処理して書き換える）
  );
  CREATE INDEX reports_user_created ON reports(user_id, created_at);
  ```
- **API**：`POST /api/reports`（ログイン必須）。中身の検査：target は肢 ID・問 ID の形、kind は4種のどれか、body は1〜500字、context は2KBまで
- **報告と退会**：報告は問題の誤りについてのものなので、退会しても消さず、`user_id` を NULL にする（誰が送ったか分からなくする）。プライバシーポリシーにそう書く
- **画面**：肢で解く・問で解くの答え合わせのあと（解説の下）に「誤りを報告」の小さなリンク。押すと、その場に欄が開く（種別の選択＋自由記述＋「送る」）。送ったら「報告を受け付けました。ありがとうございます」。ログインしていなければ「ログインすると報告できます」とだけ出す
  - 送れなかった（通信できない・上限）ときは、端末に取っておき、次の同期のときに送り直す（未送信の箱と同じ考え方。`tanto.reports.outbox.v1`）。画面には「受け付けました」と出す
- **処理の手順**（Claude のセッション）：`docs/` に手順を書く。`cd app && npx wrangler d1 execute DB --remote --command "SELECT … FROM reports WHERE status='open'"` で一覧を取り、直したら `status` を書き換える。○×の報告は公式の○×を変えない（禁止事項2）。パースの誤りか法務省の正誤訂正かを調べる

### 3. 使いすぎの制限（見えない安全網）

- **1分あたり**：Cloudflare Workers の Rate Limiting（`wrangler.jsonc` の `ratelimits`）。追加料金なし（料金表に載っていない。2026-10-20 確認）。数は Cloudflare の拠点ごとの概算（正確な数え方ではない）
  - `/api/*` の全部に、まず IP ごと（`CF-Connecting-IP`）で **1分120回**、ログインの確認のあと uid ごとで **1分60回**
  - 今の正常な使い方は、1分に1〜3回（60秒・30件ごとにまとめて送る＋画面に戻ったとき：T021）。人の手ではまず届かない
- **1日あたり**（D1 の書き込みの無料枠を守る）：uid ごとに、その日（UTC）に受け取った回答が **2万件**、報告が **50件**を超えたら受け付けない。数えるのは既存の索引（`user_id, received_at`）での読み込みだけで、書き込みは増えない
  - 2万件にした理由：全カードは9,759枚。初めてログインしたときに、端末の記録を全部まとめて送る（引き継ぎ）ので、普通の上限では正当な引き継ぎが止まりうる。超えた分は翌日に送られる（消えない）
- **超えたとき**：API は 429 を返す。アプリは 429 をエラーとして出さず（同期の表示は「同期済み」のまま変えない）、未送信の箱に残して、次の機会（60秒後・画面に戻ったとき）に送り直す
- **守れないもの**（正直に）：アカウントをたくさん作られると、uid ごとの上限は効かない。そのときは IP ごとの上限と、Cloudflare の管理画面で使用量を見ることで対応する。無料プランなので、無料枠を超えても請求は来ない（その日の同期が止まるだけで、問題を解くのは端末だけで続けられる）
- 試験しやすいように、`handleApi` の `Deps` に「制限の判定」（`limit(key): Promise<boolean>`）を渡す形にする（テストでは偽物を渡す）

### 4. プライバシーポリシー・利用規約

- **画面**：`/privacy`・`/terms`（router に足す）。フッターと、マイページの一番下からリンク
- **運営者**：ハンドルネーム（名前と問い合わせ先は、文案を見てもらうときに決める）
- **文案に書くこと**（Claude が書き、ユーザーが確認する）：
  - 集める情報：ログインした人だけ、Firebase の利用者 ID・回答の記録（どの肢に、いつ、正解したか）・誤り報告の文。名前とメールアドレスは Google／Firebase が持ち、このアプリのサーバーには置かない。Cloudflare がアクセスの記録（IP アドレスなど）を持つ
  - 使う目的：端末間の同期と、誤りの修正だけ。広告・販売に使わない
  - 預け先：Google（Firebase Authentication）・Cloudflare（Workers・D1）
  - 消し方：退会（1）。報告は送った人が分からない形で残る
  - 利用規約：無料・予告なく変更や停止がある・解説は AI が生成したもので正確さを保証しない・法務省とは関係がない・問題文の出典（法務省ウェブサイト、編集・加工している）・禁止事項（API の連打、不正なアクセス）
- **公開の判断は別**：noindex（検索に出さない）を外すかは、このチケットでは変えない
