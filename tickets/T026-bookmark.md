## 目的・背景

- 資格試験の学習サイトでよくある機能。気になった肢・解説を後で見直したい

## 議論

- 肢カード・解説に★ボタン。★を付けた肢だけで解くモード
- ★も回答ログと同じく端末に置き、ログインしていれば同期する
- 決まったこと（2026-10-22）：保存先は「端末＋サーバーで同期」（D1 に bookmarks 表を足す）

## 設計

### データ

- ★は「付けた／外した」の操作を追記していく（回答ログと同じく、消さない・書き換えない）。肢ごとに一番新しい操作（日時、同じなら操作 ID の大きいほう）を正とする。2台で別々に付け外ししても、最後の操作に合わせて同じ結果になる
- 操作1件：`{ id: 操作の UUID, s: 肢 ID, on: true＝付けた／false＝外した, at: 端末の日時 ISO }`
- 端末：localStorage `tanto.bookmarks.v1`（操作の一覧）。未送信は `tanto.bookmarks.outbox.v1`
- 名寄せ（決定018）：★は出典の肢 ID で記録し、判定はカード ID で行う（司法の肢に★を付けると、同じ予備の肢にも★が付いて見える）
- D1：`migrations/0003_bookmarks.sql`

```sql
CREATE TABLE bookmarks (
  user_id      TEXT    NOT NULL,
  id           TEXT    NOT NULL,  -- 操作 ID（端末で作る UUID）
  statement_id TEXT    NOT NULL,
  marked       INTEGER NOT NULL,  -- 1＝付けた、0＝外した
  marked_at    TEXT    NOT NULL,  -- 操作した日時（端末の時刻、ISO）
  received_at  TEXT    NOT NULL,  -- サーバーが受け取った日時（差分の取得に使う）
  PRIMARY KEY (user_id, id)
);
```

### API（呼び出しの回数は増やさない：T021）

- `POST /api/answers` の本文に `bookmarks`（省略可。1回 1,000件まで）を足す。`GET /api/answers` の応答に `bookmarks`（since より後に受け取った分）を足す
- 1日（UTC）に受け取る★の操作は 5,000件まで（使いすぎの安全網）
- 退会（`DELETE /api/me`）で bookmarks も消す。プライバシーポリシーの「サーバーに置くもの」に★を足す

### 同期

- 回答と同じ：ためて送り、起動時・ログイン時・画面に戻ったときに受け取る。初めてログインした端末は、端末の★の操作を全部アカウントに送る（引き継ぎ）。ログアウト・退会で端末の★も消す

### 画面

- 肢カード：答え合わせのあとに「☆ あとで見直す」／「★ 見直す肢に入れた」のボタン
- 元の問題・問で解くの答え合わせ：○×を出した各肢に ☆／★
- ホーム：★が1枚以上あれば「★を付けた肢を解く（N枚）」。★の肢をシャッフルして肢カードで出す（民法の改正前の年度も含める。肢カードから外した肢＝review_flag は出さない）
