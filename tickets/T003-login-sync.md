# T003 ログインと端末間同期

- 状態：議論済み（T020・T005・T002 の完了後に設計を書く）
- マイルストーン：M1 基盤
- 優先度：高
- 依存：T002（公開）・T005（肢 ID の確定）・T020（学習記録の保存層）
- 更新：2026-10-18

## 目的・背景

- ユーザーの要望：「早めにログイン機能がほしい」
- **現状**：正答履歴（`tanto.history.v1`）と FSRS の状態（`tanto.srs.v1`・`tanto.srs.new.v2`）は、ブラウザの **localStorage にだけ**ある（`app/src/history.ts`・`app/src/srs.ts`）。サーバーもアカウントもない
  - ブラウザのデータを消すと失われる。スマホと PC で共有されない。別のブラウザでも別々になる
- ログインの実質的な価値は「**記録を失わない**」と「**端末をまたいで続きができる**」の2つ

## 議論

### 先に決めること

1. **順番**（Claude の勧め：T020 → T005 → T002 → T003）
   - T020（エクスポート／インポート）：数時間で作れ、localStorage が消えるリスクを今すぐ減らせる。同期を入れた後もバックアップとして残る
   - T005（名寄せ）：肢 ID が変わると、履歴・FSRS の記録の付け替えが要る。**同期の前に ID を確定させる**と、サーバー側のデータを移し替えずに済む
   - T002（公開）：ログインはアプリが URL で開ける状態でないと意味がない（スマホから使う前提）
2. **認証とデータの置き場**（決定001では「Supabase を公開の段階で足す」）

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| **A. Supabase（Auth＋Postgres）** ← 勧め | メールのマジックリンク or Google でログイン、記録を Postgres に保存 | 決定001と一致。行単位のアクセス制御（RLS）で自分の記録だけ読める | 無料プランは1週間アクセスがないと一時停止（毎日使うなら問題になりにくい）。外部サービスに学習記録を置く |
| B. Cloudflare（D1＋Workers＋独自認証） | 公開先と同じ Cloudflare でそろえる | サービスが1つで済む | 認証を自分で作る部分が増える |
| C. Firebase | Auth＋Firestore | 実績が多い | 決定001から外れる。料金体系の把握が別に要る |

3. **同期のしかた**：端末内（localStorage／IndexedDB）を正とし、オンライン時にサーバーと差分を同期する（オフラインでも解ける状態を保つ）
   - 正答履歴：回答のログ（いつ・どの肢・正誤）を追記だけで保存すれば、端末間で衝突しない（和集合で済む）
   - FSRS の状態：回答ログから再計算できるので、**サーバーには回答ログだけを置く**のが単純（Claude の勧め）
4. **公開時の扱い**：他の人が使うなら、学習記録は個人データになる。プライバシーポリシーと削除の手段が要る（M3 で）

### 決まったこと（2026-10-18、ユーザーが勧めのとおりで合意）

- 順番：**T020（学習記録の保存層）→ T005（名寄せ）→ T002（公開）→ T003**（T020 は当初エクスポート／インポートだったが、ユーザーの指示で保存層の作り直しに変更）
- 認証とデータの置き場：**Supabase（Auth＋Postgres）**。ログイン方法（マジックリンク／Google）は設計で決める
- 同期：端末内を正とし、**サーバーには回答ログ（いつ・どの肢・正誤）だけを追記で置く**。FSRS の状態は回答ログから端末で再計算する
- ログインしなくても今まで通り使える
