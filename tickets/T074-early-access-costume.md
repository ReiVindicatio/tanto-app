# T074 ベータ版の特典：ベータ版の間にログインした人に星詠みを渡す

- 状態：完了
- マイルストーン：M3 公開
- 優先度：中
- 依存：T070
- 更新：2026-11-07

## 目的・背景

X でアプリを紹介する（T072・T073 の検索の続き。外からのリンクを増やす）。そのときに「先行特典」として、課金衣装を1着渡せるようにしたい（ユーザー、2026-11-07）。

`docs/decisions/026` では「1着を全員に常に開放する」案を見送った（その1着を買う理由がなくなる。無料で開いた衣装はあとから有料にしない決まりで、戻せない）。期間を区切った特典はそれとは別で、期間中に来た人だけがずっと着られる。期間のあとは手に入らないので、「簡単には手に入らない」方針も保てる。

## 議論（決まったこと）

- 渡すのは**星詠みで固定**（ユーザー、2026-11-07）。見本として作った衣装で、今はお試し1回
- 期間は**ベータ版の間ずっと**、条件は**期間中にログインした人全員**（ユーザー、2026-11-07）。アプリはしばらく（1年くらい）ベータ版にする。終わりの日はベータを終えるときに決める
- アプリに「β版」の表示を入れる（ユーザー、2026-11-07。このチケットで一緒に入れる）
- 経緯は `docs/decisions/027`
- 順番：特典を本番に出してから、X の投稿で告知する（あとから足すと、早く来た人が損をする）

## 設計（スキーマの変更を含む。合意を取ってから作る）

### データ（D1。migration `0005_special_owned.sql`）

```sql
CREATE TABLE special_owned (
  user_id    TEXT NOT NULL,  -- Firebase の uid
  costume    TEXT NOT NULL,
  source     TEXT NOT NULL,  -- early（先行特典）。買えるようになったら purchase などを足す
  granted_at TEXT NOT NULL,  -- 渡した日時（サーバーの時刻、ISO）
  PRIMARY KEY (user_id, costume)
);
```

「誰がどの衣装を持っているか」の表。将来の販売でもこの表を使う。

### サーバー（Worker）

- 特典の設定はコードに置く：`EARLY_ACCESS = { costume: "hoshiyomi", from: "<開始日時>", until: "<終了日時>" }`（日本時間で決めて ISO で書く）
- `/api/me`（ログインのたびに呼ばれる）で、期間の内なら `special_owned` に星詠みを入れる（すでにあれば何もしない）。返す値に `owned: ["hoshiyomi"]` を足す
- 持っている衣装の通行証：お試しと同じ形の署名つき Cookie（`tanto_own`。持っている衣装の一覧と期限。7日。`/api/me` のたびに出し直す）。`/special/<衣装>/…` は、管理者・お試し・持っている衣装のどれかなら渡す
- 退会（`DELETE /api/me`）で `special_owned` も消す（期間のあとに退会すると、もう受け取れない。画面に書く）

### 画面

- 持っている衣装は、管理者と同じように着られる（`themes.ts` の `isUnlocked`）。初めて受け取ったら、いつものお披露目を出す
- 星詠みを持っている人には、お試しのボタンを出さない
- 期間中、ログインしていない人には、マイページのログインの欄（T071）に「期間中にログインすると、星詠みをずっと着られます（〜○月○日）」と出す
- 期間のあとは、この案内を出さない

### プライバシーポリシー

- 集める情報に「受け取った特典の衣装と日時」を足し、改定日とお知らせを出す（`src/screens/Legal.tsx`）

### テスト

- 単体：期間の内と外、二度目のログインで重ならない、通行証で持っている衣装のファイルだけ渡す
- E2E（ログインあり：`e2e-sync`）：期間中にログインすると星詠みを着られ、お試しのボタンが消える。期間外なら受け取れない

## 完了条件

- 3つのテストが通る
- 本番の D1 に migration を流す（`wrangler d1 migrations apply`。過去に自動の実行が止められたので、ユーザーに流してもらう）
- 本番で、管理者の「一般で表示中」で受け取れることを確かめる

## 結果（完了時）

- 実装（2026-11-07）：`src/earlyAccess.ts`（期間。Worker とアプリが共通で読む。`until: null`）、`migrations/0005_special_owned.sql`、`worker/repository.ts`（`grantOwned`・`listOwned`・退会で消す）、`worker/special.ts`（`tanto_own` の通行証。持っている衣装のファイルだけ開く。ログアウトで消す）、`worker/api.ts`（`/api/me` で期間の内なら渡し、`owned` と通行証を返す）、`src/admin.ts`（`owned` を覚える。`isOwned`）、`themes.ts`（持っていれば開く）、お試しと「欲しい」を持っている人には出さない、ログインの欄とホームの案内、上の帯の「β版」、プライバシーポリシーの改定とお知らせ（12月7日まで）
- 同期の E2E は `EARLY_ACCESS=off` で特典を止める（お試しのテストのため）。特典は Worker の単体テストで確かめる
- テスト：パイプラインの回帰・単体、vitest 187、E2E 91、e2e:sync 8、worker の型、すべて通過
- 本番の D1 に migration を流すのは、push の**前**（表がないと `/api/me` が失敗する）
- 本番（2026-11-07）：ユーザーが migration を流したあと push（`2a63517`、CI 成功）。ユーザーが本番で「β版」の表示と、一般の見え方で星詠みを受け取って着られること、お試しと「欲しい」が出ないことを確かめた
- 直し（ユーザーの確認で）：持っている課金衣装が、まだ持っていない衣装のカードの下（一覧の一番下）に出て分かりにくかった。「特別な衣装」の先頭に持っている衣装を出し、その下に「まだ持っていない衣装」を並べる。ログインしていない人の星詠みのカードの案内も、ベータ版の間は「ログインすると、ずっと着られます」にした
