# T072 検索に載るページを増やす（サイトマップを読ませる・タイトル）

- 状態：完了
- マイルストーン：M3 公開
- 優先度：高
- 依存：T044・T045
- 更新：2026-11-07

## 目的・背景

ユーザー：「検索でいっぱい出てくるようにしてほしい」。

Search Console（2026-11-07 ユーザー確認）では、登録済みは 3,220 URL のうち 4 ページ（`/`・`/q/`・一覧1・問1。最後のクロールは 2026-10-23）。サイトマップ `/sitemap.xml` は 2026-10-23 に送ってから「取得できませんでした」のままで、検出されたページは 0。未登録のページには理由が出ていない（Google が URL を知らない）。送り直しても変わらず、削除のボタンはない。「公開 URL をテスト」は成功（Cloudflare に弾かれてはいない）。

こちらで確かめたこと：サイトマップは XML として正しく、3,220 件・重複なし・200・`application/xml`。問のページは 200 で、タイトル・説明・canonical・解説（数千字）がある。存在しない URL とアプリの画面の URL（`/subjects` など）は、どれもアプリの枠を 200 で返す。

## 議論（決まったこと）

2026-11-07、ユーザーが下の範囲で「直していいよ」（設計レビュー省略：データ・スキーマ・方針に触れない、見せ方とサイトマップの形の変更）。

- いちばんの原因は、新しいサイトで外からのリンクがなく、サイトマップも読まれていないため、Google が残りのページを知らないこと
- 条文ごと・判例ごとのページ（3問以上で出てくる条文 約1,200、2問以上の判例 約520）は**見送る**。登録が数百ページになってから考える（巡回されないうちに薄いページを大量に足すと、低品質と見られうる）
- 外からのリンク（X などでの紹介）はコードでは代われない

## 設計

`app/scripts/pages.mjs`（`npm run build` の最後に流れる）だけを直す。

1. **サイトマップを分ける**：`/sitemap.xml` を目次（sitemapindex）にし、試験・年度ごとの `/sitemaps/<yobi|shiho>-<年>.xml` と、入口の `/sitemaps/top.xml`（`/`・`/q/`）に分ける。1枚が読めないときに切り分けやすく、新しい URL として送り直せる
2. **更新日（lastmod）**：問のページは、その問の解説の生成日のうち新しいもの。一覧と各サイトマップは、含む問のうち新しいもの
3. **アプリの画面の URL をサイトマップから外す**（`/subjects`）。アプリの `index.html` に canonical（`/`）を付け、`/subjects` などアプリの画面の URL は `/` と同じページとして扱ってもらう
4. **タイトル**：和暦で書く（`H24` → `平成24年`）。問題文が「〇〇に関する次の…」の形なら、そのテーマを入れる（3,041 問のうち 約2,200 問）
   - 問：`司法試験 平成24年（2012年） 刑事訴訟法 第24問（告訴）の過去問と解説｜たんたん`。h1 も同じ年の書き方とテーマにする。年度・科目の一覧の各問にもテーマを付ける
   - 「ＡとＢの婚姻」「Ａ所有の甲土地」のような事例の当事者名（全角の英大文字・甲乙丙丁）を含むものはテーマにしない
   - 一覧：`司法試験 平成24年（2012年） 刑事訴訟法の短答式過去問と解説｜たんたん`
5. **パンくずの構造化データ**（JSON-LD の BreadcrumbList）を問と一覧のページに付ける

やらないこと：存在しない `/q/…` を 404 にする（Worker を通すと静的配信の無料の扱いが変わる。どこからもリンクされない URL なので害が小さい）。末尾の `/` への転送が 307 なこと（Cloudflare の静的配信の決まり。サイト内のリンクはすべて `/` 付き）。

テスト：E2E `e2e/pages.spec.ts` を、新しいタイトル・パンくず・サイトマップの目次と子に合わせて直す。

## 完了条件

- 3つのテストが通る
- 本番で `/sitemap.xml` が目次、`/sitemaps/*.xml` が URL の一覧を返す
- ユーザーが Search Console に `/sitemap.xml` と子のサイトマップを送る（ユーザー）

- 実装（2026-11-07）：サイトマップは目次 `/sitemap.xml` と子 33 枚（`top` と試験・年度ごと 32）、3,219 URL（`/subjects` を外した）、すべてに更新日。テーマ付きの問 2,086 / 3,041
- テスト：パイプラインの回帰・単体、vitest 178、E2E 90（問のページのテストを 3 → 4 件）、e2e:sync 8、worker の型、すべて通過
- 本番に出たら、ユーザーが Search Console で `/sitemap.xml` を送り直し、子のサイトマップ（例 `/sitemaps/yobi-2026.xml`）も1枚送って読まれるか確かめる
