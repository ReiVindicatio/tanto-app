# T020 学習記録の保存層（DB に切り替えやすくする）

- 状態：設計レビュー
- マイルストーン：M1 基盤
- 優先度：高
- 依存：
- 更新：2026-10-18

## 目的・背景

- 今の学習記録（正答履歴・FSRS の状態）は localStorage にだけある。サーバーがないので、静的サイトのままで動き、オフラインでも使え、費用もかからない
- 1台の端末だけで使うなら困らない（ログインのないクイズサイトと同じ仕組み）。ただし、端末をまたいだ共有はできず、ブラウザのデータを消すと失われる
- ユーザーの要望（2026-10-18）：**「あとで DB にして永続化したくなったときに、簡単に切り替えられる仕組みになっていればよい。エクスポートはなくてよい」**
- 今のコードは、`history.ts` と `srs.ts` が localStorage を直接読み書きしていて、切り替えやすい作りになっていない
- T003（ログインと同期）では「サーバーには回答ログだけを置き、FSRS は回答ログから再計算する」と決めた。しかし、今は回答ごとの記録（ログ）を残していない

（当初は「エクスポート／インポート」として起票した。ユーザーの指示でエクスポートはやめ、保存層の作り直しに変えた）

## 設計

### 1. 回答ログを唯一の正本にする

- 保存するのは**回答ログだけ**にする。回答1回ごとに1件を追記する（消さない・書き換えない）

```ts
type Answer = { id: string; s: string; ok: boolean; at: string };
// id：回答ごとの一意な ID（crypto.randomUUID()。同期のときの重複除去に使う）
// s：肢 ID、ok：正解したか、at：回答した日時（ISO）
```

- 正答履歴の集計（回答数・最後の正誤）、FSRS のカードの状態、今日の新規の数は、**起動時に回答ログを古い順に流し直して、メモリ上に作る**。回答するたびに、ログに追記し、メモリ上の状態も更新する
- 1万回答を流し直しても一瞬で終わる（FSRS の計算は軽い）

### 2. 保存先を差し替えられるようにする

```ts
interface RecordStore {
  load(): Promise<Answer[]>;          // 回答ログを全部読む
  append(answer: Answer): Promise<void>; // 1件追記する
}
```

- 今は `LocalStorageStore`（キー `tanto.log.v1`）だけを作る
- T003 では `SupabaseStore` を足すだけで済む。画面や、集計・FSRS の計算には手を入れない。未送信の回答を端末にためて、オンラインになったら送る、という同期の処理も T003 で `RecordStore` の実装の中に閉じ込める
- 非同期（`Promise`）にしておくのは、DB に替えたときに呼び出し側を書き換えないため

### 3. コードの置き場

| ファイル | 内容 |
|---|---|
| `app/src/store.ts`（新規） | `RecordStore` と `LocalStorageStore` |
| `app/src/learning.ts`（新規） | 回答ログから集計・FSRS・新規の数を作る処理（画面から切り離した純粋な関数。T001 で単体テストを書く） |
| `history.ts`・`srs.ts` | 中身を `learning.ts` に寄せる。画面から呼んでいる関数（`summarize`・`applyFilter`・`buildSession`・`dueSummary` など）の名前と使い方は変えない |
| `App.tsx`・`StatementDrill.tsx` | 起動時に回答ログを読み込んでからホームを出す。回答時の呼び出しを1つにまとめる |

### 4. 今ある記録の移し方

- 今の localStorage には、集計（`tanto.history.v1`）と FSRS の状態（`tanto.srs.v1`）がある。回答ごとの記録はないので、元の回答を完全には戻せない
- 移し方（勧め）：**肢ごとに1件の回答ログに変換する**（最後の正誤と日時を使う）。回答回数と FSRS の細かい状態は失われるが、「どの肢を解いたか」「前回まちがえたか」は残る
- 変換したら、古いキーは `tanto.legacy.*` に名前を変えて残す（消さない）

### 5. 確認のしかた（T001 がまだないので）

- headless Chrome で、今と同じ確認（肢カード・全年度・絞り込み・今日の復習・兄弟の抑制・新規の枠）がすべて通る
- 回答したあと再読み込みしても、回答済みの数・復習の期限・新規の残りが変わらない
- 古い形式の記録を入れた状態で起動すると、回答ログに変換される

### 6. 残るリスク（T003 まで）

- 端末をまたいだ共有はできない（1台で使う前提）
- **iPhone の Safari は、7日間そのサイトを開かないと、localStorage を消すことがある。**毎日使えば問題になりにくい。ホーム画面に追加して使うと対象外になる

## 設計で決めてほしいこと

1. 回答ログを唯一の正本にし、集計と FSRS の状態はそこから作る（保存するのはログだけ）
2. 今ある記録は「肢ごとに1件の回答ログ」に変換する（回答回数は失われる）

## 完了条件

- 学習記録の保存が `RecordStore` を通してだけ行われ、localStorage を直接呼ぶ箇所がない
- 今までの機能（履歴・絞り込み・今日の復習）がすべて同じように動く
- `docs/features.md` を更新している
