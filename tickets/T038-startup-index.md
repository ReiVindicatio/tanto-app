# T038 起動時に全部の束を読み込まない（肢カードの一覧を index に持つ）

- 状態：完了
- マイルストーン：M2 拡充
- 優先度：高（公開して検索から人が来るようになったので上げた）
- 依存：
- 更新：2026-10-21

## 目的・背景

- 起動時に、科目ごとの枚数・回答済みの数を出すため、全部の束（2026-10-19 時点で176ファイル・16MB、圧縮して約2.3MB）を読み込んでいる（`data.ts` の `useSets`）
- 2回目からは端末に保存した分（service worker）を使うが、初回やデータの更新後はスマホで待つ量になった
- 案：書き出し（export.py）で「束ごとの肢カードの ID と問の ID」だけの軽い一覧を作り、起動時はそれだけ読む。問題文は解くときに読む

## 決まったこと（2026-10-21 ユーザー決定）

- 起動時は `index.json` だけ読む。束（問題文）は解くときに読む
- **オフライン用の保存は「開いた年度だけ」**にする（T030 の「初めて開いた直後から全部を機内モードで解ける」はやめる）。初めて来た人に全データ（圧縮して約5MB）を取らせない

## 設計（設計レビューは、上の決定で代えた）

- `export.py`：`index.json` の各束に `cards`（出題できる肢カードの ID を束の ID を除いた形で空白区切り）を足す。問の ID が「束の ID-qNN」になっていない肢があれば止める
- `data.ts`：`cardRefsOf` で一覧から肢 ID・問 ID を作る。端末に古い `index.json` が残っていて `cards` がないときだけ、従来どおり束を読む
- `play.ts`：今日の○問・今日の復習は、一覧から出題する肢を先に選び、その肢を含む束だけ読む
- `sw.js`：インストール時に保存するのは画面・JS／CSS・`index.json` だけ（v3）。束は開いたときに保存（従来どおり、保存したものをすぐ返して裏で取り直す）

## 結果

- 起動時に読むデータ：全177ファイル（32MB・圧縮して約5.3MB）→ `index.json` だけ（356KB・圧縮して約27KB）
- テスト：パイプライン 33・単体 80（`data.test.ts` を足した）・E2E 30（起動時に束を読まないこと・開いた年度はオフラインで解けること）・同期の E2E 4 通過
- E2E の `totalCards` は、解く画面に切り替わるのを待つようにした（束を解くときに読むので、切り替わりに少し時間がかかる）
