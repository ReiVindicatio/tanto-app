## 目的・背景

- iPhone の Safari は、7日間サイトを開かないと保存データを消すことがある。ホーム画面に追加して使えば対象外になる
- アプリのように全画面で開ける。電波の弱い場所でも解ける

## 議論（論点の候補）

- manifest とアイコン、Service Worker で問題データと画面をキャッシュ
- 未送信の回答は今の仕組み（T003）で、オンラインに戻ったら送られる
- スマホアプリ（T019）より先に、これで十分かを見る

## 設計

### ホーム画面に追加

- `manifest.webmanifest`：名前「短答一問一答（仮称・非公式）」、短い名前「短答一問一答」、全画面（standalone）、テーマ色はブランド色
- アイコン（192・512・maskable・Apple 用180）：ブランド色の角丸の地に白で「短」。**法務省のマークや紋章を思わせる図柄は使わない**（CLAUDE.md）。SVG から Playwright で PNG を作る（`app/scripts/icons.mjs`）
- iPhone はホーム画面に追加する操作が分かりにくいので、マイページに手順（共有 → ホーム画面に追加）を出す。ホーム画面から開いているときは出さない

### オフライン（自前の Service Worker：`app/public/sw.js`）

| 対象 | やり方 |
|---|---|
| 画面（ページの読み込み） | ネットワーク優先、つながらなければ保存した index.html |
| `/assets/*`（ビルドごとに名前が変わる JS・CSS） | 保存したものを優先（中身が変わらないので） |
| `/data/*.json`（問題データ） | 保存したものをすぐ返し、裏で取り直す（次の起動で新しい解説などが反映される） |
| `/api/*` | **保存しない**（そのままサーバーへ。未送信の回答は今の仕組み〔T003・T021〕でオンラインに戻ったら送る） |

- インストール時に、index.html・そこから読む JS／CSS・`data/index.json` とそこに載る全データを先に保存する（初めて開いた直後から機内モードで解けるように）
- 保存の名前に版を付け、新しい版が入ったら古い保存を消す
- 開発中（`npm run dev`）は登録しない

### テスト

- E2E：一度開いた後に通信を切って再読み込みしても、ホームが出て肢を解ける。manifest とアイコンが配信される

## 実装（2026-10-19）

| ファイル | 内容 |
|---|---|
| `app/public/manifest.webmanifest`・`app/index.html` | ホーム画面に追加するための設定（名前・全画面・テーマ色・アイコン・iPhone 用の指定） |
| `app/public/icons/`・`app/scripts/icons.mjs` | アイコン（○×の図柄、ブランド色）。ファビコンもブランド色に変えた |
| `app/public/sw.js` | Service Worker（上の表のとおり）。新しい index.html を受け取ったら、使われなくなった古い JS／CSS を消す |
| `app/src/main.tsx` | 本番のビルドでだけ Service Worker を登録 |
| `app/src/screens/MyPage.tsx` | ホーム画面に追加する手順（iPhone・Android）。ホーム画面から開いているときは出さない |

- 実装中に見つけて直したこと：モジュールの JS は Origin 付きで読み込まれ、サーバーの `Vary: Origin` のせいで、保存したものに照合が当たらず、通信を切ると画面が真っ白になった。照合で Vary を無視するようにした（E2E で確認）
- 問題データは「保存したものをすぐ返し、裏で取り直す」ので、**デプロイで解説などが増えたとき、反映されるのは次に開いたとき**になる
- もし Service Worker に不具合があっても、`sw.js` を差し替えてデプロイすれば直せる（版を上げると古い保存は消える）

### テスト

- E2E 2件：一度開いた後に通信を切って再読み込みしても、ホームが出て、一度も開いていない年度の肢も解ける／manifest とアイコンが配信される
