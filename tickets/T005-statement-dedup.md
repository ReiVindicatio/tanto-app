# T005 同一肢の名寄せ（肢 ID の確定）

- 状態：保留（T011 の取り込み時に要否を決め直す）
- マイルストーン：M2 拡充
- 優先度：低
- 依存（再開の条件）：T011（司法試験の取り込み）
- 更新：2026-10-19

## 目的・背景

- 決定001の3：予備と司法で同じ問題が出ている場合、同一肢を1つにまとめ、出典を複数持たせる。年度をまたいで同じ記述が出ることもある
- 起票時の懸念：名寄せで肢 ID が変わると、学習記録（回答ログ）の付け替えが要る。だから同期（T003）の前にやる、という順番にした

## 議論

### 実データで数えた結果（2026-10-19）

- 予備 民法15年度（○×のある1,112肢）で、本文が同じ肢（空白・全角半角・句読点の違いをならして比較）は **4組・8肢だけ**。○×が食い違う組はない
  - 例：「代理人が保佐開始の審判を受けたときは，代理権は消滅する。」（H23 × ／ H30 ×）
- 名寄せが効くのは、**司法試験の短答を取り込んだとき**（T011）。予備の短答は司法試験と共通の問題が多いと考えられ、そこで重複が大量に出るはず（取り込んで数えるまでは推測）

### 設計上の気づき：名寄せは後からでも学習記録を移さずに済む

- T020 で、回答ログには「答えた肢の ID」（例：`yobi-2018-minpo-q03-a`）を記録する形にした
- **ログには出典の肢 ID をそのまま記録し、「どの肢が同じカードか」はデータ側の対応表で、読み込み時に当てる**ようにすれば、名寄せを後から入れても・やり直しても、ログ（端末の記録も、T003 のサーバーの記録も）を書き換えずに済む
- 必要なのは「**出典の肢 ID は一度公開したら変えない**」という約束だけ

### 選択肢

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| **A（勧め）** | M1 では「出典の肢 ID は変えない」約束と、読み込み時にカード ID を当てる仕組み（対応表が空でも動く）だけ入れる。実際の名寄せは T011（司法）と一緒に M2 で行う | T003 を待たせない。重複の少ない今、名寄せの規則を急いで決めずに済む | 予備の中の4組は、当面は別々のカードのまま |
| B | 今、予備の民法の4組も含めて名寄せまで入れる | M1 で完結する | 4組のために規則・画面（出典を複数表示）を作ることになる。司法の取り込みで規則を見直す可能性が高い |
| C | 名寄せをやめる | 何も作らない | 司法を入れたときに、同じ肢が2枚出る |

### A にした場合の中身（設計の候補）

- `docs/decisions/` に「出典の肢 ID は変えない（変えるときは旧 ID → 新 ID の対応表を残す）」を記録
- データ：`data/review/cards.json`（または export の出力）に「カード ID → 出典の肢 ID の一覧」の対応表（今は空）
- アプリ：`learning.ts` の `replay` で、回答ログの肢 ID をカード ID に読み替えてから集計・FSRS を作る。肢カードの一覧でも、同じカードの肢は1枚にまとめる（対応表が空なら今と同じ動き）
- テスト：対応表に1組入れたときに、2つの出典の回答が1枚のカードの履歴になることを単体テストで確かめる

### 決まったこと（2026-10-19）

- ユーザー：「名寄せは必要か。同じ問題が出ることは致命的とは思えない」→ Claude も同意。**保留**にする（📖 decisions/011）
- 守る約束は「出典の肢 ID は変えない」だけ。T003 の依存から外す
- 司法試験を取り込んだら（T011）、重複の実数を見て、案A（読み込み時にカード ID を当てる）で入れるかを決め直す

## 完了条件（A の場合）

- 「出典の肢 ID は変えない」約束が記録されている
- 対応表があれば、異なる出典の肢の回答が1枚のカードの履歴・復習として扱われる（単体テスト）
- 対応表が空の今は、既存の動きが変わらない（テストがすべて通る）
- 実際の名寄せ（重複の検出・出典を複数表示）は T011 に引き継ぐ
